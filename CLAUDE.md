# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Fişten Excel'e" — a Turkish-language tool for accountants: bulk-upload receipt photos, extract fields (firma, tarih, KDV breakdown, toplam) with Gemini Vision, review/edit in a spreadsheet UI, export to .xlsx. All UI copy, API status values, and error messages are in Turkish — keep it that way.

## Commands

```bash
# Setup (once): copy env templates, put a real GEMINI_API_KEY in backend/.env
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
cd backend && npm install
cd ../frontend && npm install

# Run locally (two terminals)
cd backend && npm run dev      # Express with --watch on http://localhost:8002
cd frontend && npm start       # CRA via craco on http://localhost:5600 (PORT set in frontend/.env)

# Frontend build (must compile with zero warnings)
cd frontend && npm run build

# Tests / diagnostics
python backend_test.py         # API integration tests against a running backend (defaults to http://localhost:8002/api; override with BACKEND_URL)
cd backend && npm run test:key # Validates the Gemini API key
cd backend && npm run poc      # End-to-end single-receipt pipeline test (needs API key)
```

On Windows, `baslat.bat` / `kapat.bat` / `kontrol.bat` / `test_key.bat` in the repo root start/stop/check everything (they kill only the processes listening on ports 8002 and 5600).

There is no lint script and no unit test suite; `backend_test.py` (requests-based, against a running server) is the test harness.

## Architecture

Two independent apps, no shared code. All backend routes live under the `/api` prefix.

### Backend (`backend/`, Node ESM + Express, port 8002)

The receipt pipeline is the core. One route file (`src/routes/api.js`) wires everything:

- **Upload** (`POST /api/sessions/:id/receipts`, multer in-memory) → each file is enqueued in `services/queue.js`, which runs the full pipeline with `p-limit` concurrency 3:
  `imageProcessor.js` (HEIC→JPEG via heic-convert, sharp resize to max 1568px long edge) → `gemini.js extractReceipt` (Vision extraction; on model failure automatically falls back to `gemini-2.5-flash` then `gemini-2.5-flash-lite`) → `learningService.js` (applies previously learned corrections keyed by Vergi No) → `validation.js` (total vs matrah+KDV tolerance ±0.05, date range, confidence flags) → status.
- **Three AI providers, routed by model name**: (1) `kimi`/`moonshot` prefix → Moonshot OpenAI-compatible API (`services/kimi.js isKimiModel`, `KIMI_API_KEY`, base `https://api.moonshot.ai/v1`); (2) `nvidia:` prefix **or** an `org/model`-form id containing `/` → NVIDIA NIM (`services/nvidia.js isNvidiaModel`, `NVIDIA_API_KEY`, base `https://integrate.api.nvidia.com/v1`, OpenAI-compatible, **free** dev tier; vision model set by `NVIDIA_VISION_MODEL`, default `qwen/qwen2.5-vl-72b-instruct` — Qwen2.5-VL is the strongest open VLM for receipt/invoice OCR→JSON); (3) everything else → Google Gemini (`GEMINI_API_KEY`). Routing order matters: Kimi check first, then NVIDIA, else Gemini. The default/main model is `kimi-k2.5` (set via `AI_MODEL` in `.env`). **Currently the system is intentionally Kimi-only**: the fallback chain in `gemini.js` and the `MODEL_SUGGESTIONS`/`/settings` quick-pick omit Gemini and NVIDIA (their code paths remain intact and re-enable by restoring the commented fallback entries + suggestions). Payment types (`odeme_turu`) are `nakit`/`kredi_karti`/`havale`/`bilinmiyor` (havale/EFT added for dekont). The extraction fallback chain crosses providers (selected model → `kimi-k2.5` if a Kimi key exists → NVIDIA vision model if an NVIDIA key exists → `gemini-2.5-flash` → `gemini-2.5-flash-lite`); when the provider actually used differs from the intended one, `queue.js` sets `receipt.aiNote` (serialized to the frontend, which toasts it once). Chat falls back Gemini → Kimi → NVIDIA once on failure. Kimi quirks: only `temperature=1` is accepted (so temperature is never sent) and thinking mode is disabled by default for cost/speed (`KIMI_THINKING=1` re-enables); NVIDIA accepts `temperature` (extraction sends 0) and ignores the Kimi thinking flag. Extraction, chat, diagnostics, and `test_key.js` all route through this split — keep all three paths working when touching AI code.
- **Escalation ladder** (`queue.js processReceipt`): if the first cheap read comes back `kontrol_gerekli`, the receipt is re-extracted with stronger models (`ESCALATION_MODELS`, default `kimi-k2.6,kimi-k2.7-code`) with thinking enabled (`extractReceipt(buffer, model, { thinking: true, noFallback: true })`). First clean result wins; otherwise the highest-confidence result is kept. Escalation failures are non-fatal. If critical fields (tarih/firma/toplam/kdv_detay) are missing after the first pass, the ladder is skipped and the receipt goes straight to the strongest (last) escalation model. The runtime thinking mode (`config.thinkingMode`: `auto`/`on`/`off`, settable via `PUT /api/settings`) controls whether the first pass and escalations think.
- **Chat is an agent** (`services/chatService.js`): on the Kimi path it uses function-calling (`AGENT_TOOLS`: `fis_listele`/`fis_detay`/`fis_guncelle`/`fis_sil`/`fis_onayla`/`satir_ekle`) so the assistant can edit/delete/add rows on the user's command. `runAgentLoop(session, messages, model, visitorId, completionFn)` runs ≤8 rounds and is provider-agnostic (`completionFn` is `kimiChatCompletion` or `nvidiaChatCompletion`); tools are executed through `services/receiptOps.js` (the shared edit/approve/delete/manual-add module that REST routes in `api.js` also use — keep both callers going through it). `POST /api/sessions/:id/chat` returns `{ reply, actions, changed, summary }`; the frontend refreshes the table and toasts when `changed`. The plain Gemini path is text-only (no tools); since the main model is Kimi this is fine, and the Gemini→Kimi fallback re-enters the agent loop.
- **Custom column titles**: the spreadsheet headers are user-renameable (persisted in localStorage `excel_column_titles`, applied to the xlsx export via the `?headers=` query param). Because of this, `excelImport.js` `parseExcelWorkbook` maps columns **by position, not header name** (only correct for the app's OWN export layout) — don't revert it to name-based lookup. **Foreign-Excel import**: the `/import` route runs a **quality gate** — if the deterministic parse yields 0 rows OR <50% of rows have a positive `toplam` (columns didn't line up), it falls back to `parseExcelWithAI`, which picks the **active sheet** (`Workbook.Views[0].activeTab`, else the sheet with most rows — not blindly `SheetNames[0]`), sends rows to Kimi **in 30-row chunks** (avoids the output-token limit on big files) and infers headerless/arbitrary layouts (e.g. a `DEKONT/NAKİT` column, bank column, açıklama column). AI result wins only if it produces more rows-with-`toplam` than the deterministic one; the response sets `aiUsed` (frontend toasts it). **`parseExcelWithAI` is column-map-first for speed**: it asks Kimi for just the **column map** (`{skip_rows, cols:{tarih,firma,toplam,tip,vergi_no,belge_no}}`) from a 15-row sample in ONE call, then parses every row **locally** (`buildItemsFromMap`, `inferTypesFromTip` derives belge/ödeme from a DEKONT/NAKİT column). The map also detects **KDV columns** (`matrah` = KDV-hariç, `kdv` = KDV amount, `toplam` = KDV-dahil); when matrah+kdv are present `buildItemsFromMap` derives the rate (`round(kdv/matrah*100)` snapped to 1/8/10/18/20) and builds `kdv_detay` so imported invoice lists keep their KDV breakdown. It also drops garbage rows (empty/numeric-only firma = row-counter, month-name = summary block, no positive toplam). Imports pass `skipKdvCheck:true` to `validateAndNormalize` so missing-KDV doesn't flag payment lists (only real fiş/fatura types flag it); the grid uses `pagination:100` so 3000+ row imports stay smooth — a 1000-row sheet imports in ~2s instead of minutes. It reads the sheet with `cellDates:true` (dates are Date objects; `fmtCell`→`parseDateCell` is locale-safe). Only if the map yields <40% rows-with-`toplam` does it fall back to the older **per-row chunk** path (30-row chunks sent to Kimi in parallel via `p-limit` concurrency 5). Because activeTab is often absent in accountant workbooks, big multi-sheet files import the **largest sheet** (per-sheet picking/UI is a known gap). **Excel export** (`excelExport.js buildWorkbook`, built with **ExcelJS**, NOT the `xlsx`/SheetJS pkg) is **async** (returns a Promise<Buffer>) — the `/export` route awaits it. It emits 3 styled sheets: **Fişler** (colored+frozen header, autofilter, zebra rows, borders, money/date number formats, SUM total row), **Aylık Özet** (monthly KDV breakdown for beyanname), **Firma Özeti** (per-company totals). `ResultsTable.jsx` also has a live search box + bulk "kontrol gerekenleri onayla" toolbar (bulk delete deliberately left to the chat agent to avoid accidental data loss). The export adds a **Belge Türü** column (Fiş/Dekont/e-Fatura/…, col M) and a **Kategori** column (gider türü/sektör, col N — appended at the END so existing money-column indices/formulas stay put) so dekont vs fiş and expense category can be filtered; column D is labeled **Belge No** (not "Fiş No") since it also holds dekont/fatura numbers. **Expense category** (`gider_kategorisi`): extraction classifies each receipt into one of 15 fixed slugs (`gida_market`/`akaryakit`/`yemek_restoran`/`kirtasiye_ofis`/`saglik_eczane`/`konaklama`/`ulasim`/`iletisim`/`teknoloji_demirbas`/`giyim`/`insaat_yapi`/`temizlik_sarf`/`hizmet`/`arac`/`diger`) in the JSON prompt + Gemini responseSchema + `validation.js` (VALID_CATEGORIES, invalid→null); `ReceiptPanel.jsx` shows it as an emerald badge and the export maps slugs to Turkish labels (CATEGORY_LABELS). Dekont extraction now also captures `vergi_no`/`vergi_dairesi` when the slip prints them (previously told to null them). **Delete is undoable**: `receiptOps.removeReceipt` pushes the receipt into a bounded `session.trash`, `POST /sessions/:id/receipts/:rid/restore` (via `restoreReceipt`) brings it back (re-saving its image), and the frontend delete toast shows a "Geri Al" action. `ReceiptPanel.jsx` shows the `belge_turu` badge and a "Bu Fişe Yapay Zekâya Danış" button (`onAsk` → opens `ChatPanel` with that receipt selected so its image is sent). **Column index map** (`ResultsTable.jsx`): 0-11 = Tarih…Ödeme (these are the only ones the `headers=` param covers; App.js caps it at index 11), 12 = Güven (read-only, colored red/amber/green by `updateTable`), 13 = Durum (read-only), 14 = **Harcama Türü** (`CAT_COL`, editable category dropdown backed by `gider_kategorisi`; hidden/shown by a one-click toolbar toggle persisted in localStorage `show_category_col`, applied via jspreadsheet `hideColumn`/`showColumn` — re-applied after each grid rebuild), 15 = hidden ID (`ID_COL`). If you add/reorder columns, update `ID_COL`/`GUVEN_COL`/`STATUS_COL`/`CAT_COL` and the export index cap together. **Sheet picker**: multi-sheet accountant workbooks (month/year tabs) get a `SheetPickerDialog` — the import flow first POSTs to `/sessions/:id/import/sheets` (`listSheets`) and, if >1 data sheet, lets the user choose which sheet to import; the choice is sent as the `sheet` field to `/import` (`parseExcelWorkbook`/`parseExcelWithAI` take an optional `forceSheet`). Single-sheet files skip the dialog. The dialog also offers a **"Tümü"** option (sends `sheet=__ALL__`) → `parseWorkbookAllSheets` imports every ≥2-row sheet, each through its own quality gate, in parallel (p-limit 3), concatenating the results.
- **Receipt statuses are Turkish strings and part of the API contract**: `bekliyor`, `isleniyor`, `tamam`, `kontrol_gerekli`, `hata`, `fis_degil`. Frontend polls `GET /api/sessions/:id`. The Durum column and güven cells are colored via CSS classes (`durum-*`, `guven-*` in `App.css`) applied in the jspreadsheet `updateTable` hook. `fis_degil` = the image is not a financial document: `gemini.js` prompt writes `firma_unvani:"FIS_DEGIL"`/güven 0, `validation.js` returns `notReceipt`, `queue.js` sets status `fis_degil` (escalation skipped to save tokens) and `excelExport.js` excludes those rows.
- **Document type (`belge_turu`)**: extraction classifies each image as `yazarkasa_fisi`/`e_fatura`/`fatura`/`dekont`/`gider_pusulasi`/`diger` (in the JSON prompt + Gemini responseSchema + validation `data.belge_turu`). Dekont (bank/EFT/POS slips) usually has **no KDV**, so `validation.js` does not flag a missing KDV breakdown when `belge_turu==='dekont'` and does not lower confidence for it.
- **Runtime model change** (`PUT /api/settings`): the model-name validation regex allows `/` and `:` so NVIDIA `org/model` ids (e.g. `z-ai/glm-5.2`) are accepted. `GET /api/settings` appends `config.nvidiaVisionModel` to the quick-pick `suggestions` when an NVIDIA key is set (shown as a "bedava" chip in `SettingsSheet.jsx`).
- **Duplicate detection** (`queue.js detectDuplicates`) hashes firma+tarih+toplam+fiş no after every processed receipt.
- **Error handling**: `queue.js toTurkishError()` maps Gemini/HTTP errors to user-facing Turkish messages — route new failure modes through it.

**Admin panel & analytics** (no user accounts — visitors are tracked, not registered): `store/analyticsStore.js` keeps per-visitor device/usage data **in memory**, flushed atomically to `backend/store/analytics.json` (dirty-flag, every 5s + on exit). A visitor is identified by the frontend-generated persistent `x-visitor-id` header (localStorage `visitor_id`), plus server-captured IP and parsed User-Agent (browser/OS/device); the frontend posts richer info (screen/timezone/language/platform) to `POST /api/visit` once per load. A router-level middleware in `api.js` calls `recordRequest` for every non-health/non-admin request, and route handlers call `recordEvent(visitorId, type)` for uploads/receipts/exports/chats/etc. Admin auth (`services/adminAuth.js`): `POST /api/admin/login` compares `ADMIN_PASSWORD` (constant-time, per-IP brute-force limit 5/15min) and issues an in-memory bearer token (8h TTL); `requireAdmin` guards `GET /api/admin/overview` and `DELETE /api/admin/visitors/:vid`. Frontend `AdminPanel.jsx` opens via the `#admin` URL hash. **Cost tracking**: `services/costEstimator.js` maps token usage (`_usage` threaded up from `kimi.js`/`gemini.js` through `extractReceipt`) to estimated USD via a per-model price table (overridable with `AI_PRICES` env JSON); `queue.js` and `chatService.js` call `recordCost(visitorId, …)` after every AI call. `analyticsStore` keeps an authoritative `globalCost` plus per-visitor `cost`, **per-model breakdown** (`costByModel`, keyed by model — NVIDIA free-tier models price at $0), and a **daily time-series** (`daily`, YYYY-MM-DD buckets pruned to 120 days, tracking events + cost). `getOverview` also derives `avgCostPerReceipt` and `errorRate` (needs the `errors` counter, bumped in `queue.js` when a receipt ends in `hata`). `estimateCost` now carries the `model` name in its return so `recordCost` can attribute per-model spend. `analyticsStore` also keeps a bounded **activity log** ring buffer (`logs`, max 300, pushed by `recordEvent` for notable types — sessions/uploads/exports/chats/deletes/errors/clients/imports/manualRows — with the visitor's browser/device attached); `getOverview` returns the newest 120. The admin panel (`AdminPanel.jsx`) shows the total $ banner + avg/receipt + error rate, inline-SVG daily charts (receipts & cost), a per-model cost bar list, a searchable visitor table with CSV export, and a "Son Aktiviteler" activity-log feed. These are **estimates** — the real balance is on the provider dashboards (Kimi platform.moonshot.ai · Gemini aistudio.google.com · NVIDIA build.nvidia.com). **Security hardening** lives in `index.js`: `trust proxy`, `x-powered-by` off, optional `ALLOWED_ORIGINS` CORS allowlist, and baseline security headers (nosniff / DENY frame / no-referrer / permissions-policy).

**Two-tier storage:**
- `store/sessionStore.js` — in-memory working set, 6h TTL. Receipt buffers live here for fast access; the original upload buffer is dropped right after resize.
- `store/dbStore.js` — file-based persistence: `backend/store/db.json` (atomic tmp+rename writes) holds clients (mükellef) and receipt table data; `backend/store/images/<receiptId>.jpg` holds resized receipt images (saved only when a client is selected, deleted together with the receipt/client). Image reads fall back from memory to disk after a restart (`api.js` image route, `queue.js` retry, `chatService.js`). `learning_memory.json` stores user corrections (firma/vergi dairesi by Vergi No) that get auto-applied to future extractions.

**Config quirk** (`src/config.js`): `geminiApiKey` and `model` re-read `.env` on every access, so changing the API key does not require a restart. The model is also changeable at runtime via `PUT /api/settings`.

`server.py` is glue for the Emergent platform only (supervisor starts uvicorn on 8001, which spawns and proxies to Node on 8002). It is not needed for local development.

### Frontend (`frontend/`, React 19 + CRA/craco + Tailwind + shadcn/ui)

- Single-page app: `src/App.js` owns all state (session, receipts, polling, active client) and composes components from `src/components/`. `src/lib/api.js` is the axios client (base URL from `REACT_APP_BACKEND_URL`).
- Two view modes toggled in the TopBar and persisted in localStorage (`view_mode`): `panel` (upload zone + summary cards + table/side-panel grid) and `excel` (full-width Jspreadsheet with its own toolbar for upload/import/manual row/month filter; the receipt image opens in a right-side Sheet via the "Fişi Gör" button).
- Results table uses **jspreadsheet-ce** (Excel-like grid: arrow keys, copy/paste, right-click menu), not a plain HTML table.
- UI primitives come from `src/components/ui/` (shadcn) — always use these over raw HTML controls; use `sonner` for toasts; `lucide-react` for icons (never emoji as icons).
- Interactive elements and key texts carry kebab-case `data-testid` attributes — preserve/add them when touching UI.
- `design_guidelines.md` is the binding design spec: design tokens, Turkish copy, status colors (kontrol gerekli = amber row + left border), gradient restrictions, no `transition: all`, no centered app container.

## Deployment (Netlify + Render)

The two apps deploy separately — Netlify **cannot** host the stateful Express backend. **Frontend → Netlify** (root `netlify.toml`: base `frontend`, publish `build`, SPA redirect, `REACT_APP_BACKEND_URL` env set to the backend root **without** `/api` — `lib/api.js` appends it; the value is baked at build time). **Backend → Render** (root `render.yaml` blueprint, `rootDir: backend`, `npm start`, health `/api/health`, secrets via panel; free tier has no persistent disk so `store/` resets on redeploy — uncomment the `disk:` block on a paid plan). `backend/Dockerfile` covers Docker-based hosts. Set the backend's `ALLOWED_ORIGINS` to the Netlify URL. Full step-by-step is in `DEPLOY.md`.
